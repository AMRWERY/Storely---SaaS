# Store-builder SaaS — Planning and Stitch handoff

This folder contains four planning artifacts:

- `founder-guide.md` — business model, commerce concepts, workflows, revenue, metrics, MVP, and validation.
- `architecture.md` — monorepo recommendation, app/package structure, multi-tenancy, backend modules, data concepts, and security.
- `design.md` — proposed visual system for Stitch, including colors, typography, themes, RTL, motion, responsive behavior, and accessibility.
- `stitch-prompts.md` — reusable global instruction plus page, component, and end-to-end flow prompts.

## Recommended use

1. Read `founder-guide.md` and use its validation exercises before committing to a feature roadmap.
2. Use `architecture.md` as the initial technical decision record; adjust it after backend/database spikes.
3. Give `design.md` to Stitch as the design system reference.
4. Use one prompt at a time from `stitch-prompts.md`, always together with the global instruction.

The product name `CommerceOS` and all sample prices/data are placeholders, not final business decisions.
